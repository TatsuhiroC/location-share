# 在这里 · Location Share

把一个链接发给对方，经对方明确同意后，收下一次当前位置。

**v0.1：一次性位置分享。** 原生浏览器定位 + Cloudflare Workers 接收服务，前后端同域部署。无需安装应用，你的查看页不必一直打开。

> 仓库已包含可运行的第一版。线上网址待部署后填写；仅把静态文件放到 GitHub Pages 上不能实现位置回传。

![桌面预览](docs/images/desktop.png)

## 使用流程

1. 在首页填写接收人、分享用途，选择 1 小时或 24 小时有效期。
2. 创建后，把「分享链接」发给对方，将「专属查看链接」保存给自己。
3. 对方打开页面，看到接收人、用途、数据内容和过期时间，点击「同意并分享当前位置」，再允许浏览器定位。
4. 位置获取成功后自动上传一次。只有服务确认收到，页面才显示「位置已发送」。
5. 你打开查看链接，看到经纬度、精度半径和获取时间，可按需打开地图。
6. 过期后应用记录自动清理，也可以提前删除请求。两个链接随之失效。

创建链接和打开分享页都不会立即采集位置。第一版使用明确的分享按钮，便于用户在系统授权前确认接收人及用途。

## 已实现

- 独立的提交与查看凭据，不能互换权限；提交凭据只允许读取用途、有效期等信息，不允许读取坐标。
- 256 位随机凭据，放在链接 `#` 片段中，不进入 HTTP 请求网址。服务端只保存凭据的 SHA-256 摘要。
- 打开完整链接后，在当前标签页的 `sessionStorage` 中保留权限并清理地址栏；允许刷新。存储不可用时保留完整链接。
- 精确一次位置快照，串行事务防止同时提交覆盖；相同提交编号和内容支持幂等重试。
- 定位拒绝、不可用、超时、取消、失效链接和网络错误的中文提示。
- 取消定位后，即使浏览器稍后返回定位结果，也不会发送。
- 查看页前台自动更新；后台暂停，返回后刷新；收到位置后降低查询频率。
- Durable Objects 的持久存储及清理闹钟。即使清理闹钟延迟执行，过期请求也立即拒绝访问并删除应用记录。
- 接收人可提前删除。页面不嵌入第三方地图，不加载第三方字体、统计脚本或定位 SDK。
- 点击「打开地图」才把坐标交给对应地图服务。网页定位使用 WGS84，暂不接入需要坐标转换的国内地图瓦片。
- 服务端输入验证、4 KiB 请求体上限、同源检查、禁止缓存及框架嵌入。
- 创建限流：单个来源每分钟最多 5 次，全站每天（UTC）最多 300 次。
- 访问限流：单个来源每分钟最多 120 次 API 请求，全站每分钟最多 1,000 次、每天最多 40,000 次；到达额度时拒绝新 API 请求，已有记录仍按时过期。
- 桌面和手机自适应布局；支持系统分享与手动复制。

## 本地运行

需要 Node.js 22.12 或以上：

```sh
npm ci
npm run dev
```

打开 `http://127.0.0.1:8787`。Wrangler 在本地运行真实 Worker 与 Durable Objects，数据保存在忽略提交的 `.wrangler/` 目录。

`localhost` / 回环地址可以用于开发定位。手机访问电脑的普通 HTTP 局域网地址通常不具备安全上下文，不能用来证明手机定位正常；实机请使用部署后的 HTTPS 地址。

## 部署

```sh
npx wrangler login
npm run deploy
```

默认创建名为 `location-share` 的 Worker，自动配置两个 SQLite Durable Object 命名空间，并上传 `public/` 静态资源。请将命令返回的 HTTPS 网址填入本文的线上地址，不要猜测 Worker 域名。已有同名服务时先修改 `wrangler.jsonc` 的 `name`，避免覆盖其他项目。

全部位置请求同域访问 `/api/`，不需要把 API 令牌或 Cloudflare 凭据放进前端。Cloudflare 登录信息由 Wrangler 管理，不要上传到 GitHub。费用、额度及各地可访问性以部署账号和实测为准。

## 验证

```sh
npm run check
npm test
npx playwright install chromium webkit
npm run test:browser
npm run build
```

浏览器测试会启动本地 Worker，覆盖创建→允许定位→发送→查看→刷新→删除完整流程，同时检查拒绝、取消、重试、权限隔离、正文大小、同源限制、文本注入及手机布局。

自动测试使用模拟坐标和受控的权限响应，没有采集任何真人位置。CI 中的 Worker 存储为隔离临时数据。真实 iPhone / Android 的系统定位、内置浏览器和地区网络仍需实机验证。详见 [验证范围](docs/validation.md)。

## 数据处理与边界

- 服务保存接收人、用途、创建及过期时间、凭据摘要，以及一次经纬度、精度和时间。无需手机号、账号、设备指纹或持续轨迹。
- 使用 HTTPS 传输，第一版**没有端到端加密**；服务的部署管理员能访问存储中的位置。请使用你信任的部署实例。
- 到期或主动删除会移除应用中的活动记录；不承诺托管平台备份也在同一时刻永久擦除。Cloudflare SQLite 存储可能有平台级恢复窗口，不能把“应用已删除”理解为所有基础设施副本立即消失。
- 查看链接相当于访问钥匙，任何持有它的人都能查看和删除请求。两种链接都不要放在公开帖子中。接收人及用途由发起人填写，第一版不验证发起人身份。
- 只发送一份位置快照。浏览器返回的位置来源及精度取决于系统，不能验证坐标真实，也不能保证精确 GPS；位置时间与精度会随结果显示。
- 无后台跟踪。锁屏、切换应用和网页被系统释放可能中断定位或发送。取消定位只阻止尚未开始上传的结果；已开始上传的请求可能已经被接收。
- 断网不能首次加载页面或实时回传；第一版不缓存离线位置。网络恢复后可在原页面重试，超过五分钟的定位结果需重新获取。
- 使用该实例创建请求的服务目前对访问者开放。已有创建和访问配额限制，尚未加入账号或验证码；大量公开运营前需要进一步容量与滥用评估。

## 项目结构

```text
public/               页面、样式与浏览器定位逻辑
src/worker.js         HTTP 接口、部署绑定、创建限流与清理闹钟
src/session.js        验证、权限与位置请求事务
tests/session.test.js 状态、幂等、竞争和删除测试
tests/browser/        实际 Worker + 隔离浏览器集成测试
wrangler.jsonc        Cloudflare 同域部署配置
```
