# v0.4.0 代码与安全审查

日期：2026-10-14（Asia/Shanghai）。范围：全部业务代码、部署配置、浏览器依赖、开发/验证脚本和 GitHub 自动验证。以源码审查、状态测试、真实本地 Worker 与隔离浏览器测试为主，公网仅使用少量模拟记录，没有采集真人位置或进行压力攻击。

## 已修复的发现

| 发现 | 影响 | 修复 |
| --- | --- | --- |
| 格式正确的随机编号与伪造权限会进入 Durable Object 查询 | 无权限者可用大量不同编号增加对象访问消耗 | 新链接使用角色隔离的 HMAC-SHA-256 签名，在存储访问前校验；到期时间也受签名保护，过期新链接无需存储查询 |
| 静态页面和本地地图库均经过 Worker，所有响应 no-store | 重复静态请求增加 Worker 消耗，缓存效果差 | 仅 /api/* 先经 Worker；静态资源走静态服务，使用 no-cache 保留缓存/重新验证能力；安全头由共同来源生成，API 保持 no-store |
| 非法坐标提交抛错导致事务回滚，提交次数也被回滚 | 持有分享链接的人能用错误输入绕过记录级提交限额 | 先提交限流计数，再返回校验错误；冲突覆盖尝试也消耗额度 |
| 已持有链接的人可从多个来源反复调用相同请求 | 单一来源限流不能限制分散来源的同一链接滥用 | 签名验证后增加按链接的节点限流；提交/查看/删除使用独立额度，读取额度耗尽仍能删除；过期签名直接拒绝 |
| 慢速正文读取没有应用层截止时间 | 请求可长期等待输入 | 4 KiB 上限之外增加 5 秒读取截止和流取消；非法 UTF-8 拒绝 |
| IPv6 主机地址可轮换来源限额 | 同一网络可绕过每个地址的创建次数 | 规范化 IPv6 到 /64，IPv4 映射地址规范化到 IPv4 |
| 伪造同编号链接先写入标签页缓存，再进行鉴权 | 覆盖本来有效的查看权限，刷新后打不开 | 仅服务端验证通过后保存/清理片段；伪造链接不会覆盖已验证缓存；过期和删除后清理缓存 |
| 发起人名字可包含双向格式控制符 | 名字呈现可能误导阅读者 | 限制名字长度，拒绝控制符及双向格式控制字符；页面说明名字是自填、未验证身份；动态内容仍按纯文本渲染 |
| 有效极区纬度超出 Web Mercator 范围 | 地图异常可能遮挡接收结果 | 对地图投影范围单独判断，保留坐标与地图 APP 入口并给出提示 |
| 浏览器 vendored 库靠人工同步 | npm 更新后实际上线浏览器文件可能仍为旧版本 | 自动核对锁定依赖与本地浏览器源码；允许的适配导入路径和 sourcemap 差异明确列出；检查安全头同步 |

旧版随机凭据不能仅凭签名验证。为已发出的旧链接保留固定 24 小时迁移窗口，额外限制旧路径每节点 30 次/分钟、全局 60 次/分钟和 5000 次/UTC 日，到期自动关闭。伪造的新签名不会降级到兼容路径。截止时间见验证记录；之后部署不得自动延长。

## 清理

删除零字节且未引用的 MapLibre shared 模块、旧管理路由、已无页面引用的用途/管理框/旋转动画等样式。合并重复地图链接样式。开发与浏览器测试统一启动脚本，测试使用临时隔离状态并清理，避免累计每日配额造成误报。服务端拆分为 HTTP、能力凭据、安全头及状态逻辑，便于验证存储访问前的拒绝行为。旧创建口令配置确认新版不再依赖后清理。

## 当前防护层

- 新编号具有 96 位随机数；签名使用私密 256 位服务端密钥、HMAC-SHA-256，绑定编号、到期时间和角色。密钥只作为 Worker secret 保存，首次部署脚本不输出、落盘或传入命令行；每条记录只保存凭据摘要。用户无需创建口令。
- 持有查看链接可以查看/删除；持有提交链接只能读取邀请并提交一次快照。事务、角色校验、摘要比对和幂等编号阻止越权与竞争覆盖。
- 链接固定一小时；存储闹钟清理，过期访问拒绝，记录逻辑仍处理延迟闹钟。删除清除活动记录。原有旧请求元数据保持兼容。
- 用户点击允许才调用浏览器定位；模糊位置确认之前不上传；拒绝、取消、晚到回调及过旧样本不上传。客户端不能证明位置真实性，服务端仍验证数值、时间和 consent 字段。
- 同源/Fetch-site 检查、HTTPS、CSP、禁止被嵌入、限制浏览器权限、输入校验、纯文本显示及 API no-store。没有第三方脚本和远程二维码服务；云平台注入的统计脚本被现有 CSP 阻止。
- 全局事务限制有效创建每来源 5 次/分钟、全站 300 次/UTC 日；边缘按来源再限制 API/创建尝试/读取/提交。每个链接还有独立节点额度，每条存储记录亦有认证后的查询/提交限额。
- 库版本锁定、许可证随源发布、vendor 完整性检查及 GitHub 自动测试。依赖扫描此次未报告已知漏洞，这不能证明没有未披露漏洞。

[Cloudflare 原生限流](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)按数据中心计数，且允许近似计数，不能当作精确全网额度。全站有效创建额度由独立 Admission 事务控制。[静态资源路由](https://developers.cloudflare.com/workers/static-assets/routing/worker-script/)与[静态安全头](https://developers.cloudflare.com/workers/static-assets/headers/)配置共同避免静态请求进入业务 Worker 后丢失安全头。

## 仍存在的边界

1. 创建入口公开，没有人机验证或登录。攻击者仍可从多个网络占用每日 300 次创建额度，使当天新创建受限；少量额度约束存储规模，但不能消除拒绝服务风险。下一步如遇实际滥用，可仅在创建阶段加入 Turnstile，并做服务器验证，保留分享方简单流程；需要本站的 site key 与 secret。[官方验证要求](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)。本版未启用，不应宣传已经具有机器人识别能力。
2. API 请求在应用拒绝之前仍需运行 Worker。攻击流量仍可能占用平台请求/CPU/带宽；上述配额不等于 DDoS 免疫。可根据实际流量在 Cloudflare 针对 location 子域名及 /api/requests 配置边缘规则，避免影响 PizzaSend；当前未擅自更改 zone 全局规则。
3. 两项目 Worker、存储、限流键及子域名独立，但同账号的部分平台总额度可能共享。不能保证本项目被攻击时 PizzaSend 永远不受配额影响；DNS 或 zone 全局配置故障亦可能共同影响。
4. 分享/查看链接属于持有者权限：转发查看链接就会授权查看和删除。没有端到端加密；部署管理员可访问服务端数据。删除仅承诺活动记录清除，不承诺平台备份瞬间永久擦除。
5. 自填名字未经身份验证。收到请求的人仍需确认来源。系统/browser 可返回大致位置；恶意使用者也可直接伪造坐标，网页无法证明人在该位置。
6. 地图服务能看到设备 IP 与请求的地图区域；大陆网络与实机权限/地图调起需要实际设备测试。第三方地图资源不可用时，位置详情和 APP 链接仍可用。
7. 没有执行公网压力攻击、全站真实配额耗尽测试或第三方正式渗透测试。本报告是具体版本的工程审查结果，不能承诺未来漏洞为零。

## 验证证据

20 项 Node 状态/安全测试、40 项 Chromium/WebKit 集成测试通过。覆盖签名伪造与角色混用在数据库前拒绝、过期签名、迁移截止/预算、未配置密钥时失败且不写数据、IPv6 地址归并、慢速输入超时、同链接分布式限流、独立删除限额、非法提交计数持久化、纯文本注入、缓存污染、静态安全头和极区坐标；完整分享、独立二维码解码、定位精度提醒与地图回退也复测通过。公网结果、部署标识和未验证范围见 [验证记录](validation.md)。
